## 演示顺序

### 1. 展示已有三轮结果

```bash
python -c "import json; [print(run, {k: json.load(open(f'results/{run}/summary.json'))[k] for k in ['deadline_rate','wait_avg_s','low_priority_max_wait_s','throughput_tokens_per_s']}) for run in ['fifo_real_r1','fifo_real_r2','fifo_real_r3','priority_reserved_real_r1','priority_reserved_real_r2','priority_reserved_real_r3']]"
```

重点说明：

- 交互期限达成率：FIFO 约 4%，reservation 约 71%
- 整体期限达成率：约 52% → 85%
- 低优先级最大等待：约 106 → 122 秒

### 2. 展示逐请求顺序

```bash
python -c "import json; print([(r['request_id'], r['priority_label'], r['effective_priority_label'], round(r['wait_s'],1), r['deadline_met']) for r in map(json.loads, open('results/priority_reserved_real_r1/requests.jsonl', encoding='utf-8'))])"
```

说明 R04–R13 的交互任务如何获得优先执行，R02/R16 等后台任务如何等待但最终完成。

### 3. 运行一个小型 mock 演示

```bash
python -m src.replay --run-id demo_fifo --policy fifo --backend mock --slots 2
python -m src.replay --run-id demo_priority --policy priority --backend mock --slots 2 --batch-limit 1
```

说明 mock 用于快速验证调度顺序，真实结果来自 `*_real_*` 目录。

## 讲解要点

- 优先级来源是规则表，可复现、无额外模型调用。
- 等待老化每 10 秒 +1，8 秒饥饿保护 +100，后台任务不会被无限饿死。
- `batch_limit=1` 为交互任务保留执行能力，代价是后台等待和吞吐。
- 4 个 slot 且无排队时，调度策略几乎没有效果；调度只在拥塞时有价值。
