# 进阶阶段任务介绍

## 一、任务目标

围绕大模型推理服务中的实际问题，自行确定一个开发项目。可以关注响应速度、吞吐、KV 容量、缓存复用、资源分配、调度公平性、服务恢复或其他有应用价值的目标。

通过调研确定方案，完成代码实现，并用基线对比验证效果。三条 [参考方向](选题参考/README.md) 提供场景和设计问题，同学们可以选择、组合或提出新的方向。

## 二、周期与环境

- 任务周期为一周，具体截止日期和时间以发布通知为准，在截止前通过 GitHub 提交作品。
- 使用具有相应显存容量的独立显卡，在 WSL 中以 llama.cpp／llama-server 为推理基础；可以改造服务层、引擎或适配的开源项目。
- 模型权重与推理计算放在 GPU。KV 可以按方案存放在 GPU、主机内存和磁盘，说明各层用途、容量及数据流向。
- 使用 AI 辅助编码工具，记录辅助范围与关键代码、数据和输出的核验方式。
- 根据选题确定模型、量化格式、上下文与并发规模，保留版本、模型来源、校验值和复现配置。
- 采用决策模型时，说明调用方式、模型版本、输入和输出字段，并将决策开销纳入测量。

基础阶段的测试、存储、前端与恢复功能可以继续使用。已有实现的来源、迁入版本和本阶段改动应在开发说明中清楚呈现。

## 三、选题与开发

在 `development/README.md` 说明以下内容，并在开发过程中更新：

1. 应用场景及当前问题。
2. 优化目标和可观察的判断依据。
3. 系统结构与计划开发的模块。
4. 基线方案和比较方法。
5. 工作负载、输入来源及预期验证情境。

实现可以是独立代理服务、请求调度模块、缓存管理层、引擎改动或其他可运行组件。说明自己的代码和开源项目修改，展示关键逻辑的执行结果。

`development/` 的目录结构由同学们自行设计。源码提交重点放在自己实现或修改的部分，可以提交自编模块、适配代码或补丁。依赖的开源项目通过来源链接、版本或 commit 及获取方式说明，提供能复现自己改动和运行结果的入口。

## 四、测试设计

自行组织能检验方案的固定负载，覆盖正常使用和关键边界。参考素材见 [参考测试](参考测试（仅作参考）/README.md)，也可以延续基础阶段输入或自行设计资料。

- 比较时固定模型、硬件、请求内容、到达序列和输出配置，记录所研究的变化项。
- 按方案覆盖单请求／并发、冷缓存／热缓存、不同长度或不同任务类型，说明选取依据。
- 核心比较至少完成 3 轮，保存逐请求数据及波动情况。
- 输入与已生成 token 总量应适配模型上下文和实际资源，使用所选 tokenizer 记录长度。
- 模型输出采用可核查的问题、代码测试或场景判定依据，观察优化对输出效果的影响。
- 设计与选题相关的异常，例如缓存缺失或损坏、决策超时、请求取消、资源不足或服务退出，记录处理与恢复结果。

缓存实验记录跨运行保留和清理的状态。调度实验按固定到达时间回放，并记录实际提交偏差、决策完成、入队、分配及生成时间。

## 五、观测与优化记录

选择与问题相关的指标，说明定义、统计范围和测量位置。

| 目标 | 可参考指标 |
| --- | --- |
| 响应与吞吐 | TTFT、TPOT、完成耗时、P95、成功请求数或生成 token 吞吐 |
| KV 容量 | 各存储层配置容量、实测可用 token 容量、活跃 GPU 工作集及计数口径 |
| 缓存收益 | 请求命中率、复用 token 比例、保存／恢复／预取耗时、迁移字节数 |
| 调度表现 | 各类请求等待时间、期限达成率、低优先级最大等待时间、完成率 |
| 决策表现 | 优先级判断一致性、与场景约定的吻合程度、决策耗时与调用／资源开销 |
| 服务可靠性 | 异常率、恢复耗时、中断请求处理、状态与计数完整性 |
| 资源与效果 | GPU／内存／磁盘占用、传输开销、输出准确性及代码测试结果 |

记录每项改动的目的、实现位置、配置差异、实际效果和保留决定。将优先级判断、等待、缓存加载、生成和传输纳入完整时间线，以便分析端到端收益与代价。

KV 容量用 token 表示时，区分历史保存量、当前可参与推理的上下文和 GPU 活跃工作集；说明共享或分槽方式以及复用 token 的计数。改变历史选择或注意力范围的方案，应同时检查文档问答和长上下文任务效果。

## 六、展示与提交

通过日志、图表或前端展示选题的关键状态，例如缓存分布与命中、请求队列与优先级、资源占用或其他策略执行情况，并提供基线与优化结果对比。前端可根据项目需要开发。

将自己实现或修改的代码、配置、测试、原始记录和书面报告提交到 GitHub，文件位置自行安排并在开发说明中列出。报告说明问题、设计、实现、测试、效果与代价，具体见 [提交标准](提交标准.md)。
