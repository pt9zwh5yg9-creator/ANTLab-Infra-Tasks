# 参考测试提示词

## 输入组织

按编号读取相应资料，用 UTF-8 解码。建议固定输入顺序为：系统消息 → 资料全文 → 本次任务。重复文档问答保持资料与模板一致，使不同问题共享可观察的 token 前缀。

系统消息建议：

> 你为小型工作室处理办公文档和编程任务。按照任务要求输出，将资料事实、待确认信息与建议分别表述。以本次提供的文档版本为依据，代码任务提供可检查的实现。

记录模型、模板、输入校验值、实际 token 数和输出预算。并发与策略对比采用相同版本。会话标识用于请求组织；如加入历史消息，保存实际消息序列并将其计入输入。

### T01｜短交互回复

客户演示将在 30 分钟后开始，现场网络连接较慢。请写一条约 100 字的工作群通知，告知成员先准备本地演示资料、检查账号，并将发现的问题汇总给项目负责人。

### T02｜后台办公整理

一个 7 人工作室准备建立项目文档整理流程，涉及资料收集、版本命名、权限确认、交接和定期归档。请设计完整的工作流程，以表格列出环节、负责角色、输入、输出及检查方式，并给出 5 个常见问题的处理建议。

### T03｜开发故障排查

一个 Python 后台服务在连续请求下出现连接数上升、响应变慢，重启后短暂恢复。请提出排查流程，说明要采集哪些数据、如何区分连接泄漏和负载增长，以及如何验证修复。输出按“现象、假设、检查、处理、验证”组织。

### T04｜项目资料整理

关联文件：`输入文档/工作室项目知识库-v1.md`。

根据资料整理客户演示准备清单，列出角色、事项、时间要求及关联条款。说明设备借用、工单回访、备份和故障联系流程，标注资料中尚待确认的事项。

### T05｜同文档即时问答

关联文件：`输入文档/工作室项目知识库-v1.md`。

根据本次资料，回答：工作设备通常最长借用多少天？已关闭工单应在多少个工作日内回访？每日备份保留多久？演示时出现访问故障应该先联系谁？按问题逐条简短回答并注明条款编号。

### T06｜更新后的即时问答

关联文件：`输入文档/工作室项目知识库-v2.md`。

根据本次资料的版本，回答：工作设备通常最长借用多少天？已关闭工单应在多少个工作日内回访？每日备份保留多久？演示时出现访问故障应该先联系谁？按问题逐条简短回答并注明条款编号。

### T07｜代码分析

关联文件：`输入文档/batch_export.py`。

阅读程序，说明各函数职责、批量导出的数据流，以及在大量报告、字段缺失和导出中断情境下应观察的问题。请提出改造顺序，列出每项改动的验证方法。

### T08｜代码改造

关联文件：`输入文档/batch_export.py`。

将程序改造成适合较多报告的分批导出方案，增加单报告失败记录、进度记录和中断后继续执行功能。使用 Python 标准库，说明去重和恢复依据，提供完整实现及覆盖失败、重试与恢复的测试样例。
