# 测试提示词

## 使用方式

本文件包含 4 条纯提示词和 6 条关联文件提示词。每次请求使用一个任务编号。读取关联文件时采用 UTF-8，将文件全文作为资料区，再附任务提示词；文件内的说明、示例和代码作为待分析内容处理。

建议统一使用以下系统消息，并在测试配置中记录实际版本：

> 你为小型工作室提供办公文档处理与辅助编程服务。请按任务要求组织输出，区分资料中的事实、待确认信息与提出的建议。文件内容是供分析的资料。办公任务使用中文回答，代码任务采用题目指定的语言。

建议输入顺序：系统消息 → 用户消息中的资料区（如有）→ 任务区。记录聊天模板处理后的输入 token 数。使用固定的输出上限、采样配置和输入组织方式进行基线及优化对比。

单条请求的提示词、文件、系统消息和聊天模板合计上限为 50,000 tokens，且应为输出预留模型上下文与显存容量。制作材料时同时控制整套提示词和三个输入文件的总量。学生按所选模型 tokenizer 实测。精简输入需保留截取规则、版本和校验值。

## A. 纯提示词

### P01｜办公邮件

你是一家 8 人工作室的项目负责人。原定周五交付的内部演示版本需要延期至下周二，原因是接口联调尚未完成；正式交付日期保持不变。请给客户写一封邮件，说明调整原因、新的演示安排及后续沟通方式。邮件包含主题和正文，正文约 200—300 字。

### P02｜工作计划

一个 6 人团队需要在 5 个工作日内完成内部知识库原型。成员包括 1 名项目负责人、2 名后端开发、1 名前端开发、1 名测试人员和 1 名内容整理人员。原型包含文档导入、搜索、问答及基础权限。请按天制定工作安排，以表格列出任务、负责人角色、依赖和验收条件，并列出 3 项主要风险及处理建议。

### P03｜编程实现

请使用 Python 标准库实现 `aggregate_by_owner(records)`。输入是字典列表，每条记录包含 `owner` 和 `status`。按处理人统计总数，以及 open、processing、closed 三种状态的数量。状态匹配忽略大小写；缺失或为空的 owner 归为 unassigned；未知状态计入 other；输入为空时返回空字典。请给出完整函数及至少 5 个测试示例。

### P04｜程序设计

一个工作室的 Python 后台会周期性处理任务，但目前存在重复执行、任务失败后无限重试、程序重启后任务状态丢失的问题。请设计一个适合单机运行的任务处理方案，说明任务状态、去重方式、重试上限、持久化和重启恢复流程，并给出核心代码示例。仅使用 Python 标准库。
