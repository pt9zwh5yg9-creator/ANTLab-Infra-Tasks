# 现场演示清单

## 演示前

1. 确认监督器、FastAPI、浏览器三个窗口都已打开。
2. 确认服务健康：

```bash
curl -s http://127.0.0.1:8080/health
curl -s http://127.0.0.1:8000/health
```

3. 浏览器打开 `http://localhost:8000`，确认状态卡片显示服务层、llama-server、GPU 和显存。

## 演示顺序

### 1. 纯提示词请求

```bash
curl -s http://127.0.0.1:8000/v1/chat \
  -H 'Content-Type: application/json' \
  -d '{"prompt":"用一句话介绍你自己"}'
```

展示返回中的 `request_id`、`elapsed_s`、模型输出和 `timings`。

### 2. 关联文档请求

```bash
cd ~/ANTLab-Infra-Tasks/"Basic Task/提示词与输入文档/输入文档"
curl -s -X POST http://127.0.0.1:8000/v1/chat/file \
  -F 'prompt=根据资料整理项目总体状态，不超过200字。' \
  -F 'file=@办公输入01-项目会议与进度资料.md'
```

说明文件以 UTF-8 全文读取，资料和任务分别拼接，文件内容不作为指令执行。

### 3. 前端运行记录

- 打开“运行记录”，展示 `baseline_c1`、`baseline_c4`、`optimized_c1`、`optimized_c4`。
- 点击 `optimized_c4_r1` 的“查看请求”，展示逐请求 TTFT、TPOT、完成耗时、输入/输出 token。
- 点击某条请求的“输出”，展示模型输出。

### 4. 基线对比

- 打开“基线对比”。
- 左侧选 `baseline_c4_r1`，右侧选 `optimized_c4_r1`。
- 讲解 TTFT 从约 40 秒降到约 0.7 秒，吞吐从约 54 提到约 86 tokens/s，TPOT 从约 18.8 ms 升到约 30.1 ms 的取舍。

### 5. 恢复记录

- 打开“恢复记录”，展示 `recovery_r1`：
  - 4/4 成功
  - 14 次重试
  - 12.756 秒恢复
  - `server_ready`、`health_check_failed`、`server_exit`、`restart_scheduled`、`server_start` 时间线

如需现场重新跑一次恢复测试：

```bash
cd ~/ANTLab-Infra-Tasks/"Basic Task/development"
source ~/ANTLab-Infra-Tasks/.venv/bin/activate
python -m src.recovery_test \
  --run-id recovery_demo \
  --tasks P01,D01,C02,P02 \
  --concurrency 2 \
  --retries 8 \
  --retry-delay 2 \
  --kill-after 4
```

测试期间状态卡片会短暂显示不可用，监督器重启后恢复。

## 讲解要点

- 8 GB 显存下选择 7B Q4_K_M，权重约 4.17 GiB。
- 基线 1 个 slot，4 并发请求只能排队，TTFT 约 40 秒。
- 优化为 4 个 slot、32k 总上下文、q8_0 KV、Flash Attention on；显存只增加约 25 MiB。
- 多并发吞吐提升约 61%，单请求 TPOT 变慢是共享 GPU 的代价。
- 恢复测试中，已发送请求被中断后使用同一逻辑请求 ID 重试，部分输出丢弃，逻辑请求只计一次成功。
- 输出质量仍有 P02、P03、C01、C02 等失败样例，报告中如实记录。
