# 基础阶段提交标准

## 一、时间与方式

任务周期为一周，具体截止日期和时间以任务发布通知为准。请在截止时间前将完成的项目推送到自己的 GitHub 仓库。

1. Fork 本仓库，在自己的仓库中开发，分支组织方式自行选择。
2. 按实际开发过程提交源码、配置、测试与结果，使用能够说明改动目的的 commit 信息。
3. 最终版本放在仓库默认分支，或在仓库首页明确标注提交分支。
4. 提交仓库链接、提交分支及最终 commit SHA；可同时创建 `submission-v1` 标签。
5. 在 `development/README.md` 首页注明模型信息、运行入口、报告位置及测试数据位置。
6. 确保仓库可供考核人员访问。使用私有仓库时，在截止前完成访问授权。

提交历史、改动组织、配置管理和复现说明属于项目验收内容，请保留真实开发过程。

## 二、提交内容

| 目录 | 内容 |
| --- | --- |
| `development/src/` | 性能测试、文件处理、前端、服务管理等源码及依赖声明 |
| `development/configs/` | 服务启动配置、模型配置、固定负载、基线及优化配置 |
| `development/tests/` | 功能验证、输出检查及异常恢复测试，注明运行方式 |
| `development/results/` | 逐请求原始数据、模型输出、汇总统计、优化记录和恢复测试记录 |
| `development/reports/` | 完成的书面报告与配图，首页注明最终报告文件 |

书面报告可使用 Markdown 或 PDF。报告内容参照 [报告模板](报告模板/基础阶段考核报告模板.md)，与项目数据相互对应。

模型通过下载地址、版本和校验值复现；模型权重、推理引擎构建产物、依赖环境与临时 KV 快照保存在本地，并由 `.gitignore` 管理。运行配置中的密钥使用环境变量和示例配置。

## 三、验收依据

### 环境与推理

- 在 WSL 中通过 llama.cpp／llama-server 完成 GPU 推理。
- 说明模型与硬件选择依据，提供模型计算层和 KV 在 GPU 的日志与监控证据。
- 能调用推理服务、读取输入文件并展示模型输出。

### 开发与观测

- 测试程序能够运行固定负载，支持单并发和至少一种多并发。
- 结果以文件保存，前端能够展示请求状态、输出、统计与错误记录。
- 请求 ID、运行编号、提示词编号、配置和数据能够相互追踪。

### 优化与结果

- 核心配置至少运行 3 轮，保存基线和优化结果。
- 指标口径清楚，统计结果能够从原始记录复核。
- 选择 KV 容量优化时，以 token 为单位报告配置与实测容量，说明 slot 分配、KV 精度、GPU 驻留及验证边界，并比较速度和输出效果。
- 对改动的性能效果、资源变化及输出效果进行分析；如改动导致效果下降，记录对应数据并说明处理决定。
- 办公输出检查信息提取与事实依据，编程输出检查运行结果和边界条件。

### 异常与恢复

- 记录错误发生时间、请求状态、原因及相关日志。
- 能演示服务退出后的检测、重启、就绪确认和恢复后的请求执行。
- 对中断与重试请求有明确的状态和计数处理。

### 报告与 Git

- 报告覆盖场景、实现、测试、优化、输出效果及恢复流程。
- 报告中的图表和结论标注运行编号或数据路径。
- 开源项目使用和 AI 辅助开发范围清楚，能够解释关键实现并现场调整。
- 仓库有清晰入口、有效提交历史和可复现配置。

## 四、演示准备

准备从仓库说明启动项目，展示一次纯提示词请求、一次关联文档请求、并发测试、优化对比和异常恢复。可围绕关键实现、数据统计和优化依据进行现场交流。
